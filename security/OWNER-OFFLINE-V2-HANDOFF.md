## One-command-path V2 signature preflight on the owner's Termux

**Only the owner runs the real-key check locally.** GitHub/CI runs
`--self-test` with throwaway keys and is explicitly prevented from running
`--owner-test`. This validates the **V2 OTA key** (P-256), not the PKCS12
Android APK signing key. The script signs an in-memory *synthetic* web manifest
and never publishes or generates an installable APK.

Install missing Termux prerequisites if needed:

```sh
pkg install python curl coreutils openssl-tool
```

Download an **immutable reviewed commit**, verify the public script's exact
SHA-256 **before execution**, then run the disposable tests and owner keypair
test. Paste the following into Termux; `getpass` prompts for the V2 update
private-key passphrase locally without echoing it:

```sh
cd "$HOME" || exit 1
curl -fLsS --proto '=https' --tlsv1.2 \
  'https://raw.githubusercontent.com/mhs1996mhs1996-lab/aoqat/79929c6d9bf86b66786d8c8f5477e88eabee82d9/security/owner-v2-key-preflight.py' \
  -o aoqat-owner-v2-preflight.py &&
printf '%s\n' '8acafe564a61300b528509ea97907ef90929f665e325edb88fcb29f73df12576  aoqat-owner-v2-preflight.py' | sha256sum -c - &&
python3 aoqat-owner-v2-preflight.py --self-test &&
python3 aoqat-owner-v2-preflight.py --owner-test
```

If the public script's hash mismatches, **stop**. Do not execute a different
unreviewed script. If prompted, enter the **update private V2** passphrase,
not the APK signer or archive passphrase. The expected final lines include:

```
PASS: public key format and approved fingerprint
PASS: private/public ECDSA P-256 signing match
PASS: forged payload/build/sequence/expiry signatures rejected
PASS: replay/expiry policy checked
NO UPDATE PUBLISHED; NO APK SIGNED; NO PRIVATE KEY EXPORTED
```

The script does not copy, upload, read over the network, or print the actual
private key or passphrase. Internet is only used once to **download the public
script**. It can subsequently be run without a connection. It uses the local
encrypted private PEM under `~/aoqat-keys/`; signed test content remains
in memory, and verification temporary files are automatically erased.

**This check is NOT equivalent to releasing a signed update or proving that the
existing 2.10 APK has V2 public-key verification.** Existing user installations
must not receive a V2 update until a reviewed compatible APK is installed.

## Future signed partial-update preparation (after a clean-installed V2-signed base APK is verified)

1. Obtain an owner-reviewed `build-146` HTML/JS/CSS payload and its exact
   SHA-256 hashes. Do not place Quran, prayer timetable, native code or APKs in
   this channel.
2. Choose a strictly increasing `sequence`, a future `expiresAt` within the
   allowed validity window, and create the canonical unsigned manifest using
   `security/signed-update-manifest.py` semantics.
3. On a trusted owner-controlled machine, use the locally encrypted
   `aoqat-update-private-v2.pem` **only to sign** the manifest. The owner may
   use `AOQAT_UPDATE_KEY_PASSPHRASE` as a temporary local environment
   variable; unset it immediately after signing. Never put the passphrase
   in commands, GitHub secrets, CI, repository files or logs.
4. Verify the resulting signed manifest locally with
   `security/signed-update-manifest.py verify --public-key <public-file> --build 146`
   and test rejection of a modified byte and replayed sequence.
5. Transfer **only** the signed manifest and reviewed web payload into
   `android-updates/build-146/` on the isolated security branch through an
   owner-reviewed commit. Never transfer private-key material.
6. Run the **validation-only**
   `.github/workflows/publish-signed-build146.yml` workflow with
   `expected_sequence` and the exact SHA-256 of the public signed manifest.
   Its job has read-only GitHub permissions and no deployment step.
7. The verified **V2-signed base APK must already be installed**, its actual
   release checked and accepted by the owner, and independent review completed
   before any partial-update channel can be deployed. Never deploy signed OTA
   to an old APK lacking the V2 public-key verifier.

## Android APK signer is a DIFFERENT trust chain

The `aoqat-apk-production-v2.p12` key does not sign web update manifests.
The few current recipients are **informed beta testers**, and the owner
selected a **consent-based clean installation** (uninstall old trial, then
install verified V2-signed APK) rather than legacy-signer compatibility.
A clean reinstall normally removes old private trial data, so test users
must be warned and agree **before** uninstalling. The clean-install beta
policy is `security/BETA-CLEAN-INSTALL-V2.md`.

Subsequent APK upgrades must retain the exact V2 APK signing identity.

After owner-local signing, run the read-only clean-install audit on the **real APK**:

```sh
python3 security/audit-apk-signatures.py --clean-install-beta \
  --apksigner apksigner /safe/path/to/owner-v2-signed.apk
```

This requires only the signed APK and the public certificate fingerprint pinned
in the audit code; it never reads the owner's P12/private PEM or passphrases.
PASS means signer verified across the tested Android APIs, **not** app installation,
offline features, device acceptance or permission to publish. Never use the
legacy in-place migration audit result as a rejection of an approved fresh beta
installation: Android 8/8.1 cannot install a differently signed APK over the old package.
Legacy-signature migration for a future, wider user population is separate
optional research; see `security/APK-SIGNING-ROTATION.md`.
